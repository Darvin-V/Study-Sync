# StudySync AI — AI Methods, Recommendation Engine & Evaluation

## 1. Overview of AI & Recommendation Methods

StudySync AI employs a transparent, provider-independent recommendation architecture designed for zero-cost operation and educational privacy. The platform explicitly distinguishes between **deterministic rule-based heuristics** and **experimental machine-learning models**.

### Active Production Architecture
In production, recommendations are generated by deterministic, auditable scoring engines:
1. **Intelligent Peer Matching Engine** (`server/services/matching/matchingEngine.js`): Multi-criteria two-sided matching across 8 weighted dimensions.
2. **Adaptive Learning Recommendations** (`server/services/recommendation/learningRecommendations.js`): Dynamic study action suggestions triggered by recent quiz scores, topic recency, and syllabus difficulty.
3. **Focus Coach Heuristics** (`server/services/focus/focusCoachService.js`): Session pacing analysis based on discrete duration and pause timestamps.
4. **AI Service Router** (`server/services/ai/aiService.js`): Provider router that defaults to `RuleBasedProvider` (100% free, zero external keys needed), with optional non-blocking augmentation via `GeminiProvider` when `GEMINI_API_KEY` is provided.

## 2. Study Partner Matching Algorithm

The matching engine computes a two-sided compatibility score $S(u, c) \in [0, 100]$ between requesting student $u$ and candidate peer $c$:

$$S(u, c) = \sum_{k=1}^8 w_k \cdot d_k(u, c)$$

$$\sum_{k=1}^8 w_k = 1.00 \quad (100\%)$$

### Canonical Scoring Dimensions & Weights
- **Topic Similarity (25%)**: Jaccard similarity and taxonomy path overlap in curriculum DAG (`server/services/matching/topicSimilarity.js`). Exact topic match = 100, taxonomy ancestor match = 50.
- **Skill Compatibility (15%)**: Evaluates balanced or complementary skill levels based on session intent (e.g., pairing a beginner seeker with an advanced mentor = 95).
- **Goal Compatibility (15%)**: Aligns study objectives (e.g., both preparing for "Exam Revision" = 100).
- **Schedule Overlap (10%)**: Distinguishes confirmed overlap (100) from unconfirmed availability (60 neutral baseline) and explicit schedule conflicts (25).
- **Language Compatibility (10%)**: Shared spoken/coursework study languages (primary match = 100, secondary = 75).
- **Learning Style (10%)**: Aligns preferred sprint durations (e.g., both prefer 45-minute sprints = 90).
- **Reliability (10%)**: Bayesian-smoothed historical session completion and peer ratings (prior = 85%, threshold $N \ge 3$ sessions).
- **Previous Collaboration (5%)**: Prior pairwise study satisfaction (`would_study_again`).

### Cold-Start Fairness & Anti-Monopoly Rotation
- New students with zero session history receive an honest neutral reliability prior (85%) and coursework enrollment baseline to avoid starvation.
- Candidates with scores within 5 points of the top tier are rotated using deterministic hourly Fisher-Yates jitter, preventing high-reputation accounts from monopolizing partner requests.

## 3. Adaptive Learning Recommendations

The adaptive learning engine dynamically constructs actionable recommendation cards:
- **`REVISE_WEAK_AREA` (Priority 90)**: Triggered when a student scores $< 70\%$ on a topic quiz.
- **`PRACTICE_QUIZ` (Priority 80)**: Triggered when a topic was studied $> 3$ days ago with no recent assessment.
- **`CONTINUE_TOPIC` (Priority 70)**: Triggered for active curriculum topics with pending modules.
- **`JOIN_ROOM` (Priority 65)**: Triggered when an open topic room matches the student's active subject.

### Anti-Fatigue Filtering
- Recommendations marked `dismissed` or `followed_through` are suppressed for 7 days.
- Recommendations explicitly marked irrelevant (`is_relevant = 0`) are permanently excluded.

---

## 4. Focus Coach Heuristics

- Computes the ratio of completed study duration to planned sprint duration.
- Recommends 25-minute Pomodoro sprints if a student's completion ratio $< 0.60$ across $> 3$ consecutive sessions.
- **Strict Ethical Boundary**: The Focus Coach **never** captures webcams, audio feeds, eye gaze, keystrokes, or background browser processes. All advice is framed as session pacing observations.

## 5. Phase 6 Machine Learning Benchmark Experiment

### 5.1 Experiment Objective & Protocol
Investigate whether a supervised machine-learning model (L2-Regularized Logistic Regression) can outperform the deterministic heuristic in predicting whether a recommended study activity will be followed through ($y \in \{0, 1\}$) within 7 days.

### 5.2 Production Data Readiness Audit
An audit of `server/data/studysync.db` revealed:
- 15 user accounts (all development fixtures; 0 real production end-users).
- 8 recommendation tracking records, all in lifecycle status `presented`.
- **Finding**: $N_{\text{positive}} = 0$, $N_{\text{negative}} = 0$. Zero target label variance.
- **Decision**: In strict adherence to scientific integrity, **supervised model training on production data was HALTED**.

### 5.3 Benchmark on User-Isolated Synthetic Development Harness
An isolated benchmark was executed in `scratch/ml_experiment.js` ($N = 300$, 50 users, 40 train users / 10 held-out test users):

| Metric | Heuristic Baseline | Candidate ML Model | Delta ($\Delta$) | Outcome |
| :--- | :---: | :---: | :---: | :--- |
| **Accuracy** | **50.0%** | 43.3% | $-6.7\%$ | Baseline superior |
| **Precision** | **46.0%** | 40.0% | $-6.0\%$ | Baseline superior |
| **Recall** | **88.5%** | 61.5% | $-26.9\%$ | Baseline captures more struggling topics |
| **F1-Score** | **60.5%** | 48.5% | $-12.0\%$ | Baseline superior |
| **Brier Score** | 0.290 | **0.286** | $-0.004$ | ML model slightly better calibrated |

### 5.4 Conclusion on Machine Learning
**No trained machine-learning model exists in production.**  
The deterministic heuristic baseline achieved significantly higher recall ($88.5\%$ vs $61.5\%$) and F1-score ($60.5\%$ vs $48.5\%$). The candidate ML model remains strictly experimental in `scratch/ml_experiment.js`.

## 6. Evaluation Metrics & Verification Methodology

The platform computes verified engineering metrics directly from recorded database tables (`server/services/recommendation/evaluationMetrics.js`):
- **Recommendation Acceptance Rate**: $(N_{\text{accepted}} + N_{\text{followed\_through}}) / N_{\text{total\_tracked}}$
- **Recommendation Follow-Through Rate**: $N_{\text{followed\_through}} / (N_{\text{accepted}} + N_{\text{followed\_through}})$
- **Peer Helpfulness Rate**: $N_{\text{helpful = yes}} / N_{\text{helpful\_answered}}$
- **Peer Repeat Study Rate**: $N_{\text{would\_study\_again = yes}} / N_{\text{repeat\_answered}}$
